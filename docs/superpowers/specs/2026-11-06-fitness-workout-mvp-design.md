# 魔性健身 MVP 设计文档

- 日期：2026-11-06
- 状态：待审阅
- 范围：第一阶段 MVP（Web/PWA，纯前端）

## 1. 背景与目标

做一款商业化的轻量健身产品：用户选择想锻炼的部位和时长，App 自动生成一套动作方案，由 3D 人物逐个演示，并配合与动作节拍同步的"魔性"背景音乐。用户也可以改用自己手机里的音乐。

### 1.1 已确认的决定

| 项 | 决定 |
|---|---|
| 定位 | 商业化产品 |
| 首发平台 | Web/PWA，之后可用 Capacitor 套壳上架应用商店 |
| 方案生成 | 规则引擎，不接大模型 |
| 魔性音乐 | 程序按节拍实时排程播放，与动作同步 |
| MVP 范围 | 纯前端、无登录、数据存本机 |
| 动作素材 | MVP 用现成可商用素材（desk-break）；八段锦/太极放第二阶段 |
| 技术方案 | React + React Three Fiber + Vite PWA |

### 1.2 成功标准

1. 打开网页，选"腰腹 + 10 分钟 + 入门"，3 秒内生成方案。
2. 3D 人物跟着节拍逐个演示，有倒计时、次数和中文口令，每次动作到位落在重拍上。
3. 练完生成一条本地训练记录。
4. 第一次打开后，断网也能完整训练一套。
5. 在中端安卓 Chrome、iPhone Safari 和微信内置浏览器上都能完成上述流程。

### 1.3 不在 MVP 范围内

账号、云同步、付费；八段锦/太极；大模型生成；自选歌曲的节拍识别；健康问卷；多语言；横屏适配。

## 3. 用户流程

1. **首页**：选部位（可多选）、时长、难度，点"生成方案"。首次使用先显示免责声明，用户同意后才能继续。
2. **方案预览**：按热身 / 主训 / 拉伸三段列出动作、次数和预计总时长。每个动作可以：
   - **替换**：从同部位、同类型、难度不超过所选的其他动作中挑一个，次数按目标时长重算；
   - **删除**：总时长随之减少，页面显示新的总时长，不自动补足。
   页面另有"换一套"按钮，用新的随机种子重新生成。
3. **训练**：3D 演示 + 节拍音乐 + 口令 + 进度，可暂停、上一个、跳过。
4. **完成**：显示本次时长和完成的动作数，写入训练记录。

## 4. 架构

### 4.1 核心原则

节拍时钟是唯一的时间来源。音乐、动画播放进度、口令、倒计时都从它推导，不各自计时。

### 4.2 模块

| 模块 | 职责 | 依赖 |
|---|---|---|
| `catalog` | 动作数据 `exercises.json` 和模型文件 `mannequin.glb` 的加载与校验 | 无 |
| `planner` | 纯函数 `generatePlan(input, catalog, seed): Plan` | catalog |
| `beat` | Web Audio 时钟与音效排程，发出节拍事件 | 无 |
| `player` | 训练状态机，监听节拍推进进度 | beat、Plan |
| `stage` | R3F 3D 场景，按音频时钟设定动画进度 | catalog |
| `voice` | 预录口令片段，挂在节拍上播放 | beat |
| `storage` | IndexedDB 中的训练记录与设置 | 无 |
| `ui` | 四个页面与通用组件 | 以上全部 |

### 4.3 数据流

```
用户输入 -> planner -> Plan -> player
                                 |  监听
beat 时钟 --节拍事件--> player --指令--> stage（播放哪个动画、播放速度）
          \-----------> voice（口令）
player 完成 -> storage（训练记录）
```

## 5. 动作数据

### 5.1 格式

```json
{
  "id": "standing-side-bend",
  "name": "站姿侧屈",
  "clip": "Side_Bend",
  "parts": ["腰腹"],
  "type": "main",
  "level": 1,
  "impact": "low",
  "beatsPerRep": 4,
  "defaultReps": 8,
  "sided": true,
  "cues": ["双脚与肩同宽", "侧屈时不要前倾"],
  "caution": "腰椎间盘突出者幅度减半"
}
```

| 字段 | 说明 |
|---|---|
| `parts` | 取值：肩颈、上肢、胸背、腰腹、臀腿、全身 |
| `type` | `warmup` 热身 / `main` 主训 / `stretch` 拉伸 |
| `level` | 1 入门 / 2 进阶 / 3 挑战 |
| `impact` | `low` / `high`（跳跃类为 high） |
| `beatsPerRep` | 一次动作占几拍 |
| `sided` | 是否分左右；为 true 时左右各做 `reps` 次 |
| `cues` | 动作要点，训练时轮播 |
| `caution` | 禁忌提示，预览和训练时都显示 |

MVP 收录 40-80 个动作，用 zod 定义格式，加载时校验。

### 5.2 素材制作

用一个 Blender 脚本从 desk-break 原始文件中只导出选中的动画片段，合并为一个 `mannequin.glb`，并做网格压缩（meshopt）。目标文件小于 3MB。同一脚本为每个动作渲染一张缩略图，用于预览页和不支持 WebGL 时的降级显示。

## 6. 方案生成规则（planner）

### 6.1 输入

- 部位：至少选 1 个。用户选"全身"时，所有部位的动作都参与；标着"全身"的动作，无论用户选了哪个部位都算匹配。
- 时长：5 / 10 / 15 / 20 / 30 分钟。
- 难度：1 / 2 / 3。

### 6.2 步骤

1. **筛选**：保留 `level` 不超过所选难度、且 `parts` 与所选部位有交集的动作。难度 1 时排除 `impact = high` 的动作。
2. **分段预算**：热身约 15%、主训约 70%、拉伸约 15%，每段至少 1 个动作。
3. **挑选**：每段内按所选部位轮流挑动作，避免连续两个动作练同一部位；一套方案内不重复。用带种子的随机数打乱候选，同样的输入和种子得到同样的方案。
4. **算时长**：单个动作时长 = 次数 × `beatsPerRep` × (60 / BPM)，`sided` 为 true 时乘 2。从 `defaultReps` 开始，逐个加入动作直到接近该段预算。
5. **凑整**：调整最后一个主训动作的次数，使总时长（含休息）落在目标 ±30 秒内；次数最少 4、最多为 `defaultReps` 的 2 倍。
6. **休息**：动作之间休息，难度 1 / 2 / 3 分别为 20 / 15 / 10 秒，向上取整到整小节（4 拍）。
7. **不足时**：候选动作不够凑满时长时，返回实际能生成的方案，并附带 `shortfallSeconds` 字段，由界面提示用户增加部位或缩短时长。

### 6.3 节拍对齐

| 段 | BPM |
|---|---|
| 热身 | 100 |
| 主训 | 难度 1 / 2 / 3：110 / 120 / 128 |
| 拉伸 | 80 |

- 播放速度 = 动画原始时长 / (`beatsPerRep` × 60 / BPM)。
- 播放速度必须在 0.6 到 1.6 之间。超出时依次尝试把 `beatsPerRep` 加倍或减半；仍超出则该动作不参与这一段。
- 这一检查同时放在动作库校验脚本中，提前发现不适配的动作。

## 7. 节拍引擎与音乐（beat、voice）

### 7.1 时钟

- 用"提前排程"：每 25ms 检查一次，把未来 100ms 内的音效按 `AudioContext.currentTime` 排好。
- 3D 动画每帧读取音频时钟，直接算出动画应处的时间点，不累加帧间隔，避免长时间训练后音画错开。

### 7.2 音效与风格

- 音效采样约 200KB：底鼓、军鼓、镲，以及魔性音色（"duang"、木鱼、锣、鸭叫、"嘿！"）。来源限 CC0 素材或自行录制。
- 不引入 Tone.js，自写轻量排程器。
- 每种风格 = 若干 16 拍节奏型。MVP 三种：

| 风格 | 默认用于 | 特点 |
|---|---|---|
| 电子鬼畜 | 主训 | 四拍底鼓，动作到位拍落"duang" |
| 广场舞 | 热身 | 动次打次加唢呐感音色 |
| 木鱼禅意 | 拉伸 | 慢速木鱼加低音 |

用户可在设置里把主训风格换成任意一种。

### 7.3 魔性时刻

- 每次动作的最后一拍（到位拍）落重音效。
- 每组最后 3 次逐次加一层乐器并提高音调。
- 倒计时 3、2、1 配音效；休息时切换为轻节奏。

### 7.4 口令

- 预录中文语音片段约 30 条（数字 1-20、"开始""换边""休息""最后三次""完成"等），用可商用的 TTS 生成。
- 口令在拍点上播放，播放时音乐压低约 8dB。

### 7.5 自选音乐

- 用户从手机选择音频文件，本机解码播放，不上传。最近一次选择的文件存在 IndexedDB 中。
- MVP 不识别歌曲节拍：动画和口令仍跟内置时钟，用户歌曲只作背景。可选保留一层轻点击音帮助跟节奏。

### 7.6 移动端适配

- "开始训练"按钮负责创建或恢复 `AudioContext`（浏览器要求用户点击后才能发声）。
- iOS 静音键会静音 Web Audio：同时循环播放一段无声 `<audio>`，让系统把页面当作媒体播放。
- 页面进入后台（`visibilitychange`）时自动暂停训练，回到页面时提示继续。

## 8. 3D 舞台（stage）

- 单一模型、多动画片段，动画之间 0.3 秒淡入淡出。
- 默认 3/4 正面视角，可拖动旋转，提供"正面 / 侧面"按钮。
- 镜像模式默认开启，可在设置中关闭。
- 屏幕像素比上限 2；阴影只用地面接触阴影。目标：中端安卓机 60 帧。

## 9. 训练页面

- 上方约 60%：3D 人物。
- 下方：动作名、"第 5 / 8 次"（分左右时显示"左侧 / 右侧"）、整体进度条、当前动作要点、禁忌提示。
- 底部控制：暂停 / 继续、上一个、跳过、音量、风格切换。
- 休息时显示下一个动作的名称和缩略图。

## 10. 本地存储与离线（storage）

| 数据 | 内容 |
|---|---|
| 训练记录 | 日期、方案、每个动作是否完成、实际时长 |
| 设置 | 音乐风格、音量、镜像模式、是否已同意免责声明、自选音乐文件 |

- 用 IndexedDB（通过 `idb-keyval`）存储。
- 用 vite-plugin-pwa 预缓存程序、模型、音效和口令，首次打开后离线可用。

## 11. 错误处理

| 情况 | 处理 |
|---|---|
| 模型加载失败 | 自动重试一次；仍失败则提示"网络不佳"并显示重试按钮 |
| 不支持 WebGL | 改用缩略图加文字说明，音乐和计时照常 |
| 自选音乐无法解码 | 提示"此文件格式不支持"，切回内置风格 |
| 候选动作不够 | 提示实际时长，建议增加部位或缩短时长 |
| IndexedDB 不可用（如部分隐私模式） | 训练照常，完成页提示"本次记录无法保存" |

## 12. 测试

- **单元测试（Vitest）**
  - planner：同输入同结果；时长误差 ±30 秒；三段结构；不超难度；难度 1 无高冲击；不足时返回 `shortfallSeconds`。
  - 节拍与播放速度计算，以及 `beatsPerRep` 加倍/减半的回退逻辑。
  - player 状态机：用模拟时钟快进测试准备、动作、换边、休息、暂停、跳过、完成。
- **动作库校验脚本**：格式校验；每个 `clip` 在 GLB 中存在；每个动作在所属段 BPM 下播放速度可落在 0.6-1.6。
- **端到端测试（Playwright）**：选择 → 预览 → 训练（快进时钟）→ 完成 → 有记录。
- **真机测试清单**：iPhone Safari、中端安卓 Chrome、微信内置浏览器。
- 覆盖率目标：`planner`、`beat` 的计算部分、`player` 达到 80% 以上。

## 13. 技术栈

Vite、React、TypeScript、React Three Fiber、@react-three/drei、zustand、zod、idb-keyval、vite-plugin-pwa、Vitest、Playwright。素材处理用 Blender（Python 脚本）。
